# Backend Reference

FastAPI app at `backend/app/main.py`. Routes under `app/api/routes/`, business logic under
`app/services/`, ORM in `app/models.py`, engine/session/migrate in `app/database.py`, env config in
`app/config.py`. All routers + the `/ws` endpoint are registered in `main.py`; the `lifespan` wires
the queue, printer manager, plugin host, event hub, inventory sync, and sidecar warm-up. `main.py` also serves the built SPA when `STATIC_DIR` exists:
`register_spa(app, static_dir)` mounts `/assets` and falls every other GET back to `index.html` (no-cache);
`_resolve_within(root, path)` rejects `..`/absolute/symlink escapes before a file is served. Unknown `/api/*` GETs
fall through to that catch-all too (200 + index.html, not 404).
`GET /api/v1/health` (public liveness probe) also reports build identity: `version` (package metadata) and `git_sha`
(`app/version.py`: `THEMIS_GIT_SHA`, baked in by the Dockerfile `GIT_SHA` build arg / CI; falls back to `git rev-parse`,
then `"unknown"`). The sidebar footer and Settings → About render it.

Routes are split across `app/api/routes/` and plugin-provided routers. The table below is an implementation-oriented route map, not a complete generated API specification; plugins and some capability-specific routes are mounted dynamically. Use the committed or running OpenAPI schema for the exact HTTP contract.

Core route modules are registered in `main.py`; plugin routes may be mounted during app initialization.

### Spool preflight & notifications

`spool_check.check_spool_sufficiency(needed_g, spool)` is the pure comparison (no DB/HTTP) behind
`low_stock_warning` on both `jobs.py` and `queue.py` above — each route resolves its own
(config→printer→loaded-slot→Spoolman spool) chain and calls it; see `backend-review.md` §6 before
adding a third call site instead of extracting the shared batching logic. `notify.py`
fans notifications out to the channel plugins (ntfy/Discord/email) alongside `webhook_service`, from `queue_engine._fire_webhooks`/
`_fire_notifications` on the job events; each channel's `events` list lives in its plugin settings (empty = that channel sends nothing).

Pattern for a route: define Pydantic `*Create`/`*Patch` models, a `_to_dict(row)` serializer, a
`_get_or_404`, use `session: AsyncSession = Depends(get_session)`. `HTTPException(404, "msg")` uses
**positional** detail here (match existing style). Register the router in `main.py`. Every route
(new or existing) needs `dependencies=[Depends(require_scope("<scope>"))]` — see **Auth** below.

## Auth (`app/auth.py`)

`SCOPES: set[str]` — fixed, hardcoded registry, one `read`/`write` pair per route module above (plus
`printers:control`, `apikeys:{read,write}`). `require_scope(scope)` — FastAPI dependency factory;
resolves `X-Api-Key` header or `?key=` query param → prefix lookup
→ hash compare (`services/api_key_service.py`: `generate_key()`→`(raw, prefix)`, `hash_key(raw)`→sha256
hex) → 401 if missing/invalid (unless keyless local-network access is allowed — see conventions.md), 403 if
the key lacks the required scope. Offline admin CLI: `app/admin.py` (`python -m app.admin reset-password|allow-local-login`). `require_any_key` — same
resolution, no specific scope check; used by `/ws` (`app/api/websocket.py` resolves it manually before
`websocket.accept()`, since a normal `Depends` chain doesn't apply to websocket handlers — closes with
code `4401` on failure). `last_used_at` is touched on successful resolution, throttled to roughly
once/minute per key (not written on every request). OpenAPI's `/docs` Authorize button is wired via an
`APIKeyHeader(name="X-Api-Key")` security scheme attached in `main.py` (documentation ergonomics only —
enforcement is entirely `require_scope`). `THEMIS_BOOTSTRAP_KEY` env var, checked in `_resolve_raw_key`
before any DB lookup — if set, that exact value is always accepted as a full-scope key via
`secrets.compare_digest`. Recovery path for a fully locked-out install; doesn't require an `api_keys` row
to exist.

## Services (`app/services/`)

**Slicing moved to a sidecar as of the 2026-06-23 Orca-sidecar migration** (see
`docs/superpowers/specs/2026-06-23-orca-sidecar-integration-design.md`) — `slicer_service.py` now
delegates the entire slice to a separate Laminus process over HTTP instead of invoking OrcaSlicer
locally. The old local pipeline (`PresetResolver`, `ProfileIndex`, `project_config_builder`,
`mesh_3mf_builder`, `orca_reference/`) was deleted in BIZ-261; extend the provider path
(`slicer_service.py` → `SlicingProvider` → `providers/laminus/`) instead.

**Provider boundary (BIZ-224, BIZ-202).** Core never imports the Laminus or Spoolman clients: Laminus goes through
`SlicingProvider` (`services/providers/`), inventory through the plugin host (`app/plugins/`, `services/inventory/`) — see
`docs/provider-interfaces.md`. Accessors: `get_slicing_provider()` = the DEFAULT provider (`slicing_provider_for(default_provider_id())`); the plugin is whichever serves the core `gcode.produce` capability — host selection row, else the sole enabled provider (`default_provider_id()`; also `enabled_provider_ids()`, `effective_provider_id(preferred)` = a printer's preference else the default); no registry/`ACTIVE_PROVIDER` (BIZ-290); `slicing_provider_for(plugin_id)` / `gcode_producer_for(plugin_id)` build one specific plugin's `SlicingProvider` / neutral `GcodeProducer` through the plugin instance (`LaminusConnection.slicing_provider()` / `.gcode_producer()`, so the Laminus timeout settings reach the adapter; None ⇒ not configured); the URL is `provider_url(plugin_id)` (`configured_server_url()` = the default's) = `plugin_host.effective_settings('laminus')['url']` = saved setting > deprecated `LAMINUS_SIDECAR_URL` (read by core, warns once) > `plugins/laminus/defaults.toml` (`http://orca:5000`); plugin disabled ⇒ unconfigured; connection test at `POST /plugins/laminus/test` → `state` unconfigured/unavailable/healthy), `get_format_provider()` (never None; local
file-format work), `services.inventory.provider.active_provider()/has(cap)/call(...)` (no provider ⇒ inactive). Adapter packages
`providers/laminus/` and `plugins/spoolman/` own the httpx clients, the Orca gcode/override/preset logic and
the `extra.orca_profiles` encoding; `tests/test_provider_boundary.py` fails the build if anything else imports them. Core no longer shells out to OrcaSlicer anywhere (the local thumbnail regen was removed, BIZ-284).

### Plugin host (`app/plugins/`, BIZ-202 phase 1a)

Core talks to *capabilities* (named, versioned contracts), never to a specific plugin. `PluginManifest` (id, `host_api`,
`settings_model`, `secret_fields`, `factory`, `provides`/`requires`/`optional`/`defines`, `ui`, `routers`, `migrations`,
`table_prefix`, `manufacturers` (printer models: `Manufacturer`/`PrinterModel`), `default_enabled` (enabled before any config row exists)) is the public contract; core capabilities are defined in `plugins/capabilities/` (`CORE`);
`plugins/__init__.py` is a plain-dict registry (`register_plugin`, `get_plugin`, `providers_of(cap)`, `capability_catalog()`,
`definer_of(cap)`, `load_bundled` —
a bundled plugin that fails to import is logged and skipped, Themis still boots). `host.py` `plugin_host` (started/stopped
in the `main.py` lifespan; `configure(SessionLocal)` first):

- **Active rule:** a plugin serves `cap` iff `capability_selections[cap] == id`, it is registered and provides `cap`,
  `plugin_configs[id].enabled`, its `requires` are met and its instance built; `host.active(cap)` / `host.has(cap, feature)` /
  `host.part(cap)` / `host.status(cap)` are synchronous reads of an in-memory snapshot. One instance per plugin, built when it is
  enabled and selected for at least one capability. `set_provider(cap, id|None)` selects (explicit; enables; rejects a requirement
  cycle); a sole enabled provider with no stored row is auto-selected on reload; 
  `update_config(settings=, secrets=, enabled=)` validates with the manifest's model, persists, and rebuilds the
  instance in place. Secrets are write-only (omit = keep, `""` = clear).
- **Routed capabilities (BIZ-250):** `CapabilityDef.mode="routed"` (core: `printer.client`, Protocol `PrinterProvider` in
  `plugins/capabilities/printer_client.py`; typed handle `RoutedCapability[P]`) — no selection row; **every** enabled provider serves it
  and a call goes to the provider bound to its resource: `host.active_for(cap, plugin_id)`, `host.active_providers(cap)`,
  `await host.call_for(HANDLE, plugin_id, lambda p: p.method(...))` → `CallResult[R]` (blocking methods run in a worker thread,
  async ones are awaited; same containment as `call`). `host.active(cap)` is None and `set_provider` raises for a routed cap. A provider
  must satisfy the capability's `protocol` (runtime-checked when its instance is built; a nonconforming `provides` entry is rejected).
  The bundled printer plugins do not provide `printer.client` yet: they expose their client class as `factory` and the factory resolves it
  per printer row (`printers.md`).
- **Choose-one and fan-out capabilities (BIZ-250):** `CapabilityDef.mode` is `exclusive | routed | choose_one | fan_out` (`BUILDS_ALL` =
  the three that build every enabled provider). `choose_one` (e.g. slicing): the selection row is the capability **default**;
  `host.resolve(cap, preferred=, eligible=)` → `Resolution(plugin_id, outcome)` is per-resource preference → default → blocked, eligibility
  checked before dispatch, and a dormant/ineligible preference **blocks** (outcomes `preference_dormant|preference_ineligible|
  default_unavailable|default_ineligible|no_provider|not_choose_one`) — never a silent fallback. `host.call_choose(...)` = resolve + `call_for` (a bare `call_for` does not re-check eligibility);
  `host.eligible_providers(cap, eligible)` feeds selection UIs. `fan_out` (e.g. notifications): no selection row; `await host.fan_out(HANDLE,
  fn, timeout=)` calls every enabled provider concurrently, each contained on its own (`dict[plugin_id, CallResult]`). Cache-bearing capabilities key on provider identity: `slice_cache.CacheKeyInputs.provider` (always part of the hash, BIZ-291 — the provider id is the resolved plugin's, so a different
  provider never shares a key; inventory's cache is already keyed `(provider, kind)`). Contract tests:
  `tests/plugins/test_capability_modes.py`. `notify.channel` (BIZ-252) is the first fan-out capability; `gcode.produce` (slicing) is the first `choose_one` one, consumed by `slice_resolution` (BIZ-291).
- **Containment:** every core → provider call is `await host.call(cap, method, *args, timeout=)` (on the part serving `cap`) → `CallResult(ok,
  value, error, reason)`; it never raises (timeout + catch-all), logs with the plugin id and records
  `plugin_configs.state.last_error` (`last_ok_at` on recovery; only transitions are persisted). The queue loop never
  awaits it. A provider that can't be built is reported (`build_error`) and inactive, never fatal.
- **Plugin migrations:** `plugins/migrations.py` runs each registered plugin's `migrations/vNNN_*.py` (`version/name/up/down`,
  `down` required) after core migrations in `init_db`, tracked in `plugin_schema_versions`; tables must start with
  the plugin's `table_prefix` (default `<id>_`); a failing migration is rolled back (savepoint) and reported, not fatal.
- **Guard:** `tests/test_no_provider_in_core.py` — core files may not name Spoolman (ratchet allowlist that only
  shrinks) or Local inventory (plugin package only).

## Key flows (where to change behavior)

- **Claim eligibility** → `printer_manager.is_printer_ready` + `queue_engine._try_claim_for_printer`. Gate add/changes here. **Slicing-provider gate (BIZ-291)**: for a non-pre-sliced job the claim calls `slice_resolution.resolve_slicing(printer, filename)`, which runs the neutral `resolve_work` over the enabled `gcode.produce` plugins (the printer's `preferred_slicer_plugin_id`, else the capability default) and probes only the chosen one with `status(2)`. A `PRODUCE` outcome carries the `provider_id` that dispatch then slices with (`SliceRequest.provider_id`, the cache key's `provider`, the tool-mapping hook and the staleness fingerprint all use it — never the global default). A `BLOCKED` outcome blocks the job (never fails it) with the decision's message: *down* (not configured / not ready / unreachable — `recoverable`) keeps the old texts ("<Plugin> is not ready / is unreachable — slicing paused", "<Plugin> sidecar not configured — slicing paused"); *hard* blocks (preference disabled/removed, provider can't take this printer or input, none enabled, several enabled with no default) never fall back to another provider and never use the cache. With the provider **down**, a job with `allow_cached_slice` may still claim when `_cached_version_for_claim` finds a usable cached version for **this** printer's slice, keyed to the resolved provider (BIZ-201, per printer): the claim passes and `_run_slice_and_print(cache_only_version=…)` prints exactly that version; if it's gone by dispatch and the provider is still down, `_release_cache_only_claim` re-blocks (never slices, never `slice_failed`); if it is back it just slices. The claim applies dispatch's staleness rule too (a version dispatch would reslice never carries a claim). Request/key building is shared via `_slice_params` + `_slice_request` so claim and dispatch agree on the key.
- **Filament gating / AMS mapping** → `services/filament_matching.py` (`evaluate(config, loaded, conflicts)` → `Verdict{eligible, plan[SlotUse], reasons}` for the single ask, every `filament_map` colour and pinned `tool_index`; `conflicts_for(loaded)`; `plan_for`; `still_loaded`) over `services/filament_tuple.py` (the tuple, `satisfies`, `split_type` suffix rules, `conflicts`). Slot dict shape `manufacturer,type,subtype,color,filament_profile,ams_tray_id,reported`. DB `printer.loaded_filaments` is the source (AMS auto-synced via `on_ams_change`, which replaces the tuple). `GET /jobs/{id}/details` → `printer_configs[].filament_match`.
- **Spool deduction** → `inventory/deduction.completion_uses(config, loaded, grams, breakdown)` (the spool bound to each slot that PRINTED, per used slot; no bound spool ⇒ a note, `job.deduction_skipped`, and an `inventory.no_spool_tracked` event via `warn_untracked`) + `snapshot_refs`; resolved by the inventory subscriber from the job's config + the event's `loaded_filaments` (the payload's `inventory` list is legacy).
- **Multi-material remap** → `slicer_service.tool_mapping_hook` (bound as `SliceRequest.prepare_hook`, only for clients with `slice_tool_mapping`) → `SlicingProvider.apply_tool_mapping` → `snapmaker/remap.remap_3mf` + `snapmaker/paint_remap.remap_paint_color`. Change remap logic there; a new tool-changer vendor sets `slice_tool_mapping = True`.
- **Slice → print** → `_run_slice_and_print`. Actual slicing happens off-process in the Laminus sidecar (`slicer_service.py` → `SlicingProvider`/`providers/laminus/`), not locally — see the Services table above. `client.orca_export_args` decides artifact format; `start_print(opts)` with `ams_mapping` for AMS vendors.
- **Background estimates** → `queue_engine.spawn_estimate`/`run_estimate`, gated by `queue_config.estimates_enabled`. Writes `jobs.estimate_*` guarded by an `estimate_token` (bumped on every re-request) so a stale in-flight estimate can never clobber a newer one.
- **Spool low-stock preflight** → `spool_check.check_spool_sufficiency`, called from both `jobs.py` and `queue.py` — see **Spool preflight & notifications** in the Routes section above.
- **Job events from printers** → `services/job_reporter.py` (`JobReporter` per plugin on `PluginContext.job_reporter`, `JobDetailsReader`/`Writer`) → `queue_engine.mark_printing` / `complete_job` / `fail_started_job` / `note_print_blocked` (atomic claims; details and `job.started|complete` in the same transaction; origin = the printer's plugin id, `core` for the queue/admin). `handle_print_complete(printer_id)` is the adapter for the printer-client callback. Details live in `services/job_details.py` (`set_details`, `get_details`, `field_catalog`); routes `GET /jobs/{id}/detail-fields`, `GET /job-fields` (`api/routes/job_fields.py`).
- **Printer liveness** → `PrinterManager.sample_connectivity/liveness/newly_dead` (online / undead / dead against `queue_config.printer_dead_after_minutes`), `QueueEngine._liveness_pass` (start of every `_process_queue`; the loop's wait shortens to the next dead deadline), `_declare_dead` → `requeue_dead_print` (job.failed origin core, top of the queue) / `_release_sliced_job`, `on_connectivity` (wake for a dead printer back, a pending sliced job, or a changed filament slot).
- **A job nothing could take** → `QueueEngine._sweep_unmatched_jobs` (end of `_process_queue`): a due, promoted `queued` job that no printer except a dead one could take (compat config, pre-sliced eligibility, `filament_matching`; model targets are synced first; a block's reworded reason is updated quietly, one announcement per block) is `blocked` with a reason starting `NO_MATCH_PREFIX` ("no eligible printer"), publishes `job.blocked` and fires the webhook/notification; the sweep releases its own blocks when a match appears. Every other `_block_job` also publishes `job.blocked` (no webhook for a per-printer cause).
- **Plate-clear / ready-for-work** → set on `status=printing` in `_run_slice_and_print`; cleared by `/plate-cleared`. `is_printer_ready` reads it.
- **Cancel ↔ stop** → `jobs.cancel_job` stops the assigned printer (`asyncio.to_thread(client.stop_print)`) when status in `{printing,paused,uploading}`; `printers.stop_printer` reconciles the running job → `cancelled`.
