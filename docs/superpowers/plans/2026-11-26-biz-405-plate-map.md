# BIZ-405 — Plate map (neutral geometry → interactive view + SVG snapshot)

Linear: BIZ-405. Branch: `feature/biz-405-plate-map`. Blocks BIZ-404 (closeout) and BIZ-396 (skip objects), which
will call it later with their own data. **Isolated:** no API route, no DB column, no jobs/parts/printers/plugins/
Laminus/queue code is touched. Everything is driven by the fixture corpus.

## Scope brief (themis-planning)

- **Change shape:** new shared frontend component (no screen, no route in `App.tsx`) + one pure backend module
  (no route). Closest precedent: `contracts/ui-schema-cases.json`, one corpus run by a TS and a Python validator.
- **Invariants in play:** vendor/provider boundary (the component names no vendor, slicer, job, part or printer —
  enforced by a new import/vocabulary boundary test); styling (`app.css` tokens only, `styleTokens.test.ts` budget
  unchanged — state colours are caller *data*, not literals); responsive (one breakpoint, `minmax(0, …)` tracks,
  ≥44px targets at ≤1024px); coverage floors are ratchets.
- **Boundary check (separation of concerns):** the component takes labels, footprints, caller states and
  selectable flags, and reports labels. It never maps an object to a Themis part. That mapping belongs to the
  callers (BIZ-404/BIZ-396). No boundary is crossed by this design.
- **Doc drift:** none found. `docs/agent/frontend.md` gains a row for the component.

## Decision: where the snapshot is rendered

**Chosen: a server-side Python renderer (`backend/app/services/plate_map.py`) that re-implements the documented
layout spec below, with both implementations checked against one corpus of fixtures with hand-computed expected
results (`contracts/plate-map-cases.json`).**

| | Server-side Python renderer (chosen) | One shared TS renderer |
|---|---|---|
| Saved snapshot (BIZ-404 stores it with the closeout) | Server renders from data it already holds | Browser renders; the server either stores browser SVG (forbidden) or stores data and every later viewer re-renders — no file for notifications/exports |
| "Server never accepts markup" | Natural: the renderer's only input is the neutral layout dict, validated with unknown keys rejected | Only holds if the server never stores the output, which defeats a *saved* snapshot |
| Runtime | Python only (the container has no Node at runtime) | Needs Node on the server to render without a browser |
| Drift risk | Two implementations of ~150 lines of maths | One implementation |
| Mitigation | Shared corpus with **expected** numbers (not "TS output = Python output"), both validators share error messages, both renderers' *output markup* is parsed and checked against the same expected points | — |

The drift cost is real but bounded: the maths is small, specified here, and every rule has a corpus entry that
both sides must reproduce from hand-computed values. If a rule changes, the corpus changes and both suites go
red until both sides follow.

## Input: the neutral plate (snake_case JSON, same in TS and Python)

```jsonc
{
  "bed": { "width": 256, "depth": 256, "origin": { "x": 0, "y": 0 } } | null,
  "states": [ { "id": "ok", "name": "Printed", "color": "#2e9e5b" } ],          // 1–6, ids unique
  "objects": [ {
    "label": "Bracket #1",                                                       // non-empty, unique on the plate
    "state": "ok",                                                               // one of states[].id
    "selectable": true,
    "footprint": { "polygon": [[x, y], ...] } | { "box": [x0, y0, x1, y1] } | null
  } ]
}
```

- Bed coordinates in mm. **+X points right, +Y points away from the operator** (toward the back of the printer).
- `origin` = where bed (0,0) sits, measured in mm from the bed's **front-left corner** (`{0,0}` front-left,
  `{175,150}` centre of a 350×300 bed, `{width, depth}` back-right with all-negative coordinates). Optional, default `{0,0}`.
- `footprint: null`, or `bed: null`, = no geometry: the object appears in the list only.
- No key outside this schema is accepted (an `svg`/`markup`/anything else key fails validation on both sides).

### Validation (both sides, same message substrings; corpus `invalid` cases)

`unknown key <k>` · `bed: width and depth must be positive numbers` · `bed: origin must be finite numbers` ·
`states: 1 to 6 states required` · `states: duplicate id` · `states: id, name and color must be strings` ·
`objects: label must be a non-empty string` · `objects: duplicate label` · `objects: unknown state` ·
`objects: selectable must be a boolean` · `objects: label has invalid characters` · `states: name has invalid characters` · `footprint: polygon needs at least 3 points` ·
`footprint: coordinates must be finite numbers` · `footprint: zero area` ·
`footprint: box must be [x0, y0, x1, y1] with x0 < x1 and y0 < y1` · `footprint: needs polygon or box`.
Booleans are not numbers (Python `bool` is an `int` subclass — excluded explicitly). Every number must be within ±100000 mm
(`MAX_MM`: keeps JS `toFixed` out of exponent notation and Python out of `OverflowError`). Labels and state names must be
XML 1.0 characters (no control characters, no lone surrogates), so every accepted plate yields a parseable, UTF-8 snapshot.
A bad **colour** is not an error: anything but `#rgb`/`#rrggbb` renders the neutral fill (`fill: null` in the
layout), so a caller value can never reach an attribute unchecked.

## Layout spec (the one set of rules; `layout.ts` and `plate_map.py` both implement it)

Let `W, D` = bed width/depth, `M = max(W, D)`, bed extent `minX = -origin.x`, `maxY = D - origin.y`.

1. **Transform** bed → view: `vx = x - minX`, `vy = maxY - y`. The bed is the view rect `(0, 0, W, D)`; the
   front (smallest Y) is at the bottom of the screen. View units are mm, so aspect ratio is exact.
2. **Box** `[x0,y0,x1,y1]` = polygon `[[x0,y0],[x1,y0],[x1,y1],[x0,y1]]` before transform.
3. **viewBox** = union(bed rect, every object's view bbox) grown by `margin = 0.04·M` on all sides. Off-bed
   objects are therefore always inside the picture, never clipped. Rendered with `preserveAspectRatio="xMidYMid meet"`.
4. **Off-bed flag:** any view vertex with `vx < -ε`, `vx > W+ε`, `vy < -ε` or `vy > D+ε` (`ε = 1e-6`).
5. **Tiny objects:** `minHit = 0.06·M`. If the view bbox is narrower or shallower than `minHit`, the object gets a
   hit rect centred on its bbox centre, `max(w, minHit) × max(h, minHit)`; it is drawn as a dashed ring so the
   object stays visible. (≈19px on a 256 mm bed drawn 320px wide.)
6. **Draw order / overlap:** by polygon area descending, ties by input order. Smaller objects sit on top, so they
   stay clickable over big ones; identical footprints: the later one is on top.
7. **Hit test (view only):** walk draw order top-down; the first object whose polygon contains the point
   (even-odd ray cast — follows concave/rotated shapes, not the bbox) or whose hit rect contains it wins. If that
   object is not selectable the click is ignored (it does not fall through).
8. **Anchor** (number marker): area centroid's y; on the horizontal line through it, the midpoint of the widest
   span inside the polygon. Stays inside concave shapes where the centroid and bbox centre fall outside.
9. **Patterns:** state *i* (input order) gets `["solid","diagonal","dots","cross","horizontal","checker"][i]`, so
   states differ by pattern as well as colour (greyscale/colour-blind safe). Hence the 6-state cap.
10. **Labels:** always escaped (React text / `xml.sax.saxutils`-style escaping in Python). Map markers are numbers
    (input order + 1); the label lives in the list (CSS ellipsis + `title`) and the snapshot key, truncated to 40
    code points + `…`.
11. Numbers are written with ≤3 decimals; the corpus compares with tolerance 1e-3. (Exact ties may round differently —
    JS `toFixed` vs Python `format` — a byte-level difference only, inside the tolerance.)
12. "Not on map" is flagged only when the plate has a map (an object without a footprint on a drawn plate); a
    list-only plate flags nothing, in the view and the snapshot alike.

## Output

- **`<PlateMap plate onObjectClick />`** (`frontend/src/components/plateMap/`): SVG map + state legend + object
  list. Map click and list click both highlight the object (map outline ↔ list row `aria-current`) and report its
  label. Non-selectable: dashed outline, faded fill, list row disabled, clicks ignored. Off-bed: warn outline +
  "Off bed" chip. No geometry: list alone. Invalid plate: `notice warn` with the validation message.
- **`render_snapshot_svg(plate) -> str`** (Python): bed outline, objects (fill + pattern overlay), markers,
  tiny-object rings, a legend (pattern swatch + state name) and a numbered key. No route yet; BIZ-404 adds one.
  `id_prefix` (default `pm`) names the pattern ids, for several snapshots inlined in one page.

## Fixture corpus — `contracts/plate-map-cases.json`

Each case: `plate` + partial `expect` (only the keys present are checked): `view_box`, `objects.<label>.{points,
off_bed, hit, anchor, pattern, fill}`, `draw_order`, `hits` (bed-mm point → label or null; view only),
`list_only`. Plus an `invalid` list (`plate`, `message`).

| Fixture | Tricky part | Hand-computed expectation |
|---|---|---|
| `square-front-left` | axis direction (front at bottom, X not mirrored) | Front box y10–40 → view y216–246; Back → y10–40; Left box x10–40 stays left |
| `centre-origin` | origin at centre, negative coords | 350×300, origin (175,150): box (−10..10) → view (165..185, 140..160); corner box at (0..10, 290..300) |
| `back-right-origin` | origin not front-left, all coords negative | origin (220,220): box (−30..−10) → view (190..210, 10..30) = top-right |
| `scale-wide-large` | very large, non-square bed; min hit from the larger side | 1000×200 → viewBox (−40, −40, 1080, 280); 3 mm dot → 60 mm hit rect |
| `scale-small-portrait` | very small, portrait bed | 40×120 → viewBox (−4.8, −4.8, 49.6, 129.6) |
| `tiny-object` | minimum hit area | 2 mm box → hit rect (93.32, 147.32, 15.36, 15.36); click 6 mm away hits, 9 mm away misses |
| `overlap` | predictable pick, reachable via list | input [Small, Large, Twin A, Twin B] → draw order [Large, Twin A, Twin B, Small]; centre click → Small; twin click → Twin B |
| `concave-l` | concave hit-test + anchor | click in the notch → null; on both arms → L; anchor (25, 217.364) inside the L |
| `rotated-rect` | rotated hit-test | 45° rectangle; bbox corner → null; centre → hit |
| `off-bed` | drawn and flagged, never dropped | half-off, fully-off and behind-the-bed objects flagged, viewBox grows to (−30.24, −34.24, 340.48, 300.48) |
| `labels` | long/odd labels, escaping | 200-char, `<script>`, `"><img onerror>`, `&`/quotes, emoji/CJK, RTL — text equals input, no element injected; key truncated at 40 code points |
| `six-states` | more than colour | 6 states → 6 distinct patterns; a markup-ish colour → neutral fill |
| `mixed-selectable` | non-selectable looks different / ignores clicks | |
| `missing-footprint` | partial geometry | object without footprint: list only, "Not on map" |
| `no-geometry` | no bed | `list_only: true` |
| `hostile-states` | state-name escaping, exact colour match | `<b>&"x</b>` name is text; `#abc" onload=…` and `#abcdef0` → neutral |
| `closeout-example` | eyeball only (3-state closeout look) | |
