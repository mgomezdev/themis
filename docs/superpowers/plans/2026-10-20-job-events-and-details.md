### 7. Printer liveness: "dead after N minutes offline" setting (spec §2a exception)
- Setting: `QueueConfig.printer_dead_after_minutes` (int, default 30, `0` = never declared dead = today's behavior; max 1440). Core queue setting (not vendor-specific), next to `check_interval_minutes`: migration `v056_printer_dead_after.py` (add column, idempotent, `down` drops via the repo's pattern), `models.py:340`, `api/routes/settings.py` (`QueueConfigOut`/`QueueConfigIn`, floor/ceiling like `check_interval_minutes`), `frontend/src/api/queue.ts:285` type, `SettingsScreen.tsx` field beside the check interval (+ tests; many tests stub the config, add the key), `contracts/response-keys.json` if queue config keys are listed, regen `openapi.json`.
- Three states per printer, computed by `PrinterManager.liveness(printer_id, cutoff_minutes, now)`: **online** (`client.connected`), **undead** (offline for less than the cutoff), **dead** (offline for the cutoff or longer). `offline_since` is tracked in memory on the connected->offline edge (sampled from `client.connected`, authoritative); a printer not connected at process start counts from boot. No DB column (a restart restarts the clock; documented).
- While **undead** the printer is a full participant in queue processing, including the blocked evaluation (task 8): it still counts as a match, jobs are not blocked on its account. A blip that heals before the cutoff triggers **nothing**: no wake, no reprocess, no event. (Today's behavior of not claiming onto a disconnected printer is unchanged: claim still needs `is_printer_ready`.)
- On **dead** (once per outage, edge-triggered by the sweep): for a job `printing` on that printer: publish best-effort `job.failed` (`origin="core"`, reason "printer offline for more than N minutes", `phase:"print"`), fire the usual failed webhook/notification, record the failure in details (`last_failure`), then **requeue at the top**: `status="queued"`, `queue_position = min(queue_position of queued jobs) - 1` (or 0 when none), `assigned_printer_id=None`, delete that printer's `GcodeFile` row + file, `block_reason=None`. One transaction using the same conditional-UPDATE claim as completion so a late `complete` and the dead sweep can't both win. No deduction (no `job.complete`); the earlier `job.started` snapshot stays and a later start writes its own. `awaiting_plate_clear` stays set for that printer (a half-printed part may be on the bed), so when it returns the user still has to clear the plate.
  - Documented exception to the "after start only the user releases" rule (spec §2a): a dead printer cannot hold its job. Update spec §2a accordingly (done with this plan edit).
  - Known risk (document in `docs/operations.md`): the printer may in fact still be printing; on return its state is not idle, so it stays unclaimable until the physical print ends and the plate is cleared, but the job may be printed a second time elsewhere. That is the trade the setting makes.
- On **dead -> online** (the only reconnect that matters): call the wake callback so the queue re-evaluates (this reopens jobs blocked for "no match", task 8). Wake callback = `printer_manager.set_wake_callback(...)` bound to `queue_engine.wake` in `main.py` (no queue import in `printer_manager`). Reconnect before the cutoff wakes only if the printer has pending work (next bullet).
- **Pending work on return (undead or dead -> online).** An undead idle printer may have had a job sliced for it while offline: the queue's offline pass (`_process_queue`, `slice_only`) leaves it `sliced` with a `GcodeFile(printer_id)` row (`assigned_printer_id` is None at that stage; the gcode row is the tie, see `_try_resume_sliced_job`/`_has_pending_sliced_job`, `queue_engine.py:~1220-1260`). When a printer goes offline->online (any duration) and `_has_pending_sliced_job` is true for it, call the wake callback; the normal ready path then runs `_try_resume_sliced_job`, which uploads and starts it **only if the printer is idle and its plate is clear** (`is_printer_ready`); if it is not idle (or awaiting plate clear) nothing starts and the job stays `sliced` until it is. A printer with no pending sliced job and a heal before the cutoff still triggers nothing. Implement the check in the liveness edge handler (one indexed SELECT on the online edge only, not per telemetry tick).
- **Dead printer with a `sliced` job** (not yet printing): a dead printer cannot take it, and `sliced` jobs are not claimable by other printers, so on the dead edge return it to `queued` keeping its queue position, delete that printer's `GcodeFile` row + file, and write no `job.failed` (it never started). Same sweep, same transaction pattern.
- Timely dead declaration: the loop's wait uses `min(check_interval, _seconds_until_next_schedule(), _seconds_until_next_dead_deadline())` (same pattern as `queue_engine.py:~482-488`), where the deadline is the earliest `offline_since + cutoff` among offline printers (floor 1s). Also run the liveness sweep at the start of `_process_queue` and in `_reconcile_printing_jobs` (which today skips disconnected printers, so a job on an unreachable printer sits in `printing` forever; that is the bug this fixes).
- Tests (`tests/services/test_printer_liveness.py`, fake clock injected; never `sleep`): (a) offline 5 min with cutoff 30 -> state undead, a `printing` job untouched, no event, no wake; (b) crossing the cutoff -> job `failed` event once (`origin="core"`), row now `queued`, `assigned_printer_id` None, `queue_position` below every other queued job, printer's gcode row gone, `awaiting_plate_clear` still True; (c) dead sweep run twice -> still one `job.failed`; (d) printer returns before cutoff -> no wake, no events, job still `printing`; (e) returns after cutoff -> exactly one wake, no replay of the failure; (f) cutoff `0` -> never dead (job stays `printing`); (g) a `complete` arriving concurrently with the dead sweep -> exactly one winner (assert one outbox row, final status); (h) the loop's wait timeout shortens to the dead deadline (unit test of `_seconds_until_next_dead_deadline`); (i) setting round-trips through `GET/PUT /settings/queue` and rejects out-of-range values; (j) undead printer still counts as a match for task 8 (lives in that test file); (k) idle undead printer with a `sliced` job comes back before the cutoff -> exactly one wake, and the next cycle uploads and starts it (job `printing`, `job.started` published once); (l) same, but the printer returns non-idle or awaiting plate clear -> wake happens, nothing starts, job stays `sliced`, and it starts later once ready; (m) printer with no pending work heals before the cutoff -> no wake; (n) dead printer with a `sliced` job -> job `queued` at its old position, gcode row and file gone, no `job.failed`, and another ready printer can then claim and slice it.
- Docs: `docs/agent/backend.md` (liveness states), `docs/agent/data-model.md` (new column), `docs/user-guide.md`/`operations.md` (setting + risk), `docs/events.md` (job.failed from core with `phase:"print"`).

### 8. `job.blocked` when waiting cannot get a job pulled (core-initiated, `origin="core"`; unassigned jobs only)
- Definition (confirmed): `blocked` = a job that is up for work (status `queued`, due: `not_before` passed, project promoted) and **no printer in the fleet could take it**. Waiting can't fix it: something must change in the fleet or the job. Examples: the job needs a P1S and no P1S exists; the job asks for black PA-CF and no machine has it loaded. A printer that fits but is merely busy or plate-uncleared still counts, so the job stays `queued`.
- Which printers count: **online or undead** (offline for less than `printer_dead_after_minutes`, task 7); **dead printers are excluded**. Plugin not dormant and `queue_on` (my call, shout if wrong: a printer whose queue the user switched off is excluded; only a user action brings it back). Offline-but-undead printers count with their last-known `loaded_filaments`, so a flaky network never blocks a job or reprocesses the queue.
- Per-printer test (reuse, do not duplicate rules): a counted printer matches when it has a `job_printer_configs` row for the job (explicit pick or materialized from a make/model target by `model_targets.sync_targets_for_printer`), the pre-sliced eligibility verdict (`gcode_eligibility`) is not "never", the config is not `slice_failed` (that path already blocks per printer), and `filament_matching.evaluate(config, printer.loaded_filaments, conflicts)` is eligible.
- Re-evaluation triggers (no new wiring beyond task 7): a printer going dead->online (wake), `on_ams_change` when loaded slots actually change (add the same wake callback call there), a printer added/updated, and a printer crossing the cutoff (the dead sweep). Blips never wake. Test: a slot change wakes once; dead->online wakes once.
- Reason text from the evaluator: no compatible printer row -> "no eligible printer: no <model/target> printer exists"; otherwise the shared `Verdict.reasons`, e.g. "no eligible printer: no loaded filament matches Black PA-CF on any printer". Constant prefix `NO_MATCH_PREFIX = "no eligible printer"` marks blocks this sweep owns.
- Recovery (automatic): each cycle the sweep re-checks `blocked` jobs whose reason starts with `NO_MATCH_PREFIX`; when a match now exists it sets them back to `queued`. Blocks from other causes are left alone. Adding a compatible printer, a dead printer returning or loading the filament therefore releases the job on the next cycle (prompt, via the wakes above) even if the matching printer is busy.
- No head-of-line stall: an unmatched job must not hold up jobs behind it. The claim loop already skips an ineligible job (`cand_fit.eligible` false -> continue) and a job with no config for the printer is not a candidate; keep it that way. Test it explicitly (job B behind blocked job A is claimed).
- **Overturns a documented invariant**: `docs/agent/conventions.md:38` and `CLAUDE.md`-adjacent notes say "a mismatch never blocks" (BIZ-316; v053 even reverted such jobs to `queued`). New rule: a *per-printer* mismatch still keeps the job `queued`; a *fleet-wide* mismatch blocks (and notifies). Update `conventions.md`, `docs/agent/backend.md` and the job-detail UI text if it says "stays queued".
- Tests (`tests/services/test_queue_unmatched_block.py`; each fails without the change): (a) target model with no printer -> one cycle -> `blocked`, one `job.blocked` (`origin="core"`, `entities.job_id`, payload `{reason, phase:"queue"}`), webhook + notification once; (b) black PA-CF asked, no online printer has it loaded -> blocked; (c) same job, one *busy* online printer has it loaded -> stays `queued`, no event; (d) a *dead* / queue-off / dormant printer that has the filament loaded does NOT count -> job blocked; (d2) that printer comes back (dead->online) -> queue woken and the job returns to `queued` in that cycle; (d3) an *undead* offline printer (below the cutoff) that has the filament loaded DOES count -> job stays `queued`, no event, no wake; (e) second cycle, same reason -> no second event; (f) filament then loaded on any printer (or compatible printer added) -> job returns to `queued` and is claimable, no new `job.blocked`; (g) a job blocked for another reason (slice failure) is not touched by the recovery pass; (h) job behind the blocked one is claimed on a ready printer; (i) a `printing` job is never swept; (j) a not-yet-due or unpromoted-project job is not evaluated.
- `queue_engine.py`: one shared helper used by `_block_job` (when `not already` and the UPDATE hit): `hub.publish(job.blocked, origin="core", payload={reason, phase})` after commit, then webhook/notification with the reason. New per-cycle `_sweep_unmatched_jobs(fleet snapshot)`: read all printers' `loaded_filaments` once, one SELECT of due `queued`/`blocked` jobs with their configs, evaluate in memory, no per-job I/O; call from `_process_queue` before the claims. The slice-failure path (`~1182`) and `_release_cache_only_claim` publish through the same helper so every `blocked` transition emits one event.
- `JobBlockedPayload` not added (best-effort class, free-form `{reason, phase}`); document in `docs/events.md`; the registry description already says "no eligible printer".
