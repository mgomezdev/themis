Project Builder with print groups and pooled packing

The example below is a "Living wall kit" project. It mixes 3MF plates, a 3MF object, STLs and a pre-sliced plate, split across two print groups. The fleet is 3× Bambu P1S, A1 mini, H2D, Snapmaker U1 and Sovol SV08. Profile names and part sizes are examples. The 3MF sections on the Items screen really collapse; everything else is static.

Group banner

A strip under the section tabs, on Items and Groups. Badges in order: All, Default Group, one per added group (name, items, parts), "+ New group". The badge you select filters the list: All shows every row coloured by group (this screen). Drag a row (⋮⋮) onto a badge to move it; dropping on "+ New group" creates and names one.

Row checkboxes

Every row and section header has a checkbox for bulk actions (next screen). Dragging a checked row moves every checked row.

Navigation

Section tabs (Details · Items · Groups · Review) are always visible and freely clickable, with counts and a "to fix" badge. The bottom bar adds Back / Next. Nothing is lost moving between tabs, and "Save draft" keeps it all.

Collapsible sections

One section per source file (click a header; Hanging rail is collapsed). A collapsed header still shows the summary and a colour dot per item, so group membership reads at a glance. "By group" re-sorts the same rows under group headers instead.

Item cases

3MF plate × qty (bundle of the plate's objects), 3MF object × qty, STL × qty, gcode × qty (never packed, no group). Packing rule per item: Split / Together / Solo / Locked.

Default Group

Every project has one, so a user who never makes groups just sets its printers and process profile and queues. New items land in it. It has the same settings as any group and can be renamed, but not deleted. If it ends up empty, it adds nothing to the queue.

Filter

Selecting any group badge, Default Group included, shows only that group's items. All shows everything, coloured by group.

Bulk actions

Move to group, packing rule, filament, qty, remove. A section or header checkbox selects all its rows; the dash means some are selected. The header checkbox only selects what the current filter shows.

Creating a group

Click "+ New group" (here or on Items): it adds a badge with an editable name and opens its settings. A new group starts with no eligible printers (opt-in), and is packed when a printer picks it up.

Eligible printers as badges

Only the chosen ones show, each with × to remove. "+ Printer" opens the menu shown open here: a group of printers (Any printer, or any printer of a model; yellow) or a specific printer (blue). Entries already added, or covered by a model you picked, are greyed out.

Same as New Job

New Job's printer step switches to this badge picker too, so both flows match. Each badge gets one process profile row.

Change

"Any printer" is new, and New Job gets it too, so the two flows stay identical. Today New Job offers specific printers and Any <model> only.

Queue order

Badge order is queue order. Drag "Show pieces" ahead of "Structure" and its jobs queue first.

No "All" here

The Groups tab hides the All badge: there is no "all groups" settings view. Default Group stays because it is a real group with its own settings. The banner component just takes a show-All flag.

Pack at claim vs fixed bed

"Structure" is a pool (option 4). "Show pieces", collapsed here, packs now for 256 × 256, and any printer whose bed contains that can take it (options 1–3).

Process profile per group

"Printer default" uses the profile set on each printer. A row per model overrides it, so draft vs fine quality is just two groups.

Fit checks

Each part is checked against its group's beds (X, Y and Z). A part that fits none of them is an error, so a pool can't get stuck.

Fix links

Each problem names the tab that fixes it. The Review tab badge counts what's open; "Queue project" stays disabled until it's zero.

Succeeded / failed counts

Each part starts at all succeeded, 0 failed. Raising Failed lowers Succeeded by the same amount. "Nothing failed" and "Whole plate failed" fill in every row at once.

Partial bundle failure

A "Together" bundle is reported part by part, and only failed parts reprint. Failed objects from a locked plate reprint alone, in their original positions.

Auto-restore

Failed parts go back automatically: to the pool for packed parts, or as a new job for solo, locked and gcode items.

Retry limit

Counted per part, against the Themis-wide limit (2). A held part waits on the project page for "Reprint" or "Drop".

Later (earmarked)

Making a new project from the plates whose parts are held. Not in this design.

Printer waivers

Repeat failures of one part on one printer waive that printer for that part only, in every project. It skips (falls through) any job containing the part until someone clears the waiver.

Part-level history

Every failure is logged per part (not per plate or bundle) with printer and time, so a part that keeps failing stands out. Bundle membership is shown so the context isn't lost.

Change

Today job_item_failures counts per project item and plate only, from guessed per-plate counts. This needs counts per part per job, from the real list of what was on each plate.

Retry limit placement

Moved to the existing Settings → Print defaults page, next to the current slicer-cache setting, saved the same way.

Per-printer settings

Only the per-printer items stay in the printer editor: the default process profile (next to the machine profile from the model), "Single colour only", and this printer's part waivers with Clear.

Test print

Each waived part has "Test print". It makes a one-part job for this printer only. If the printer is idle and holds no queue job, it's sent now. Otherwise the printer stops claiming queue work and the test is its next print. A good result offers Clear waiver.

Printer flag

Per printer, on its page: at the flag level (example 3) the printer shows a warning on Fleet, a sign it may need a plate wash or maintenance. The higher stop level pauses the printer's queue until waivers are cleared. It is 0 (off) by default.

Two thresholds

Retries count failures on different printers (a model problem → hold). "Waive after" counts failures on the same printer (a printer problem → waive). Both default to 2. A waiver belongs to the part (its file content and plate/object), so it carries across projects.
