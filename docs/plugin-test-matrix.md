# Plugin compatibility and failure matrix (BIZ-304)

Every plugin scenario that crosses a boundary (install, registry, capability resolution, HTTP API, UI contribution, provider failure,
removal) and the automated test that holds it. Single-component behaviour stays in that component's own tests; the rows below are
the integration view, and the new cross-boundary scenarios live in `backend/tests/plugins/test_plugin_matrix.py`.

* Everything listed runs in the default CI run (`pytest`, `vitest`); `backend/tests/plugins/test_plugin_matrix_doc.py` fails when a row
  names a test that does not exist, is skipped, or when an area below has no row.
* No physical printer and no external service: plugins are fakes (`tests/plugins/dummy_plugin.py`, `conformance.py`), printers are the
  mock plugin or `tests/virtual_printers/`, Spoolman and Laminus are in-process fakes.
* A test is written `path::function` (Python) or `path::title substring` (frontend), relative to `backend/` or the repo root.

Areas: `manifest-host-api`, `dependencies`, `failure-recovery`, `enable-select`, `ui-contributions`, `data-retention`, `events`, `workflows`.
